# Rubric: is this plan ready to post and build from?

## Checks

| Check              | Evidence                                                                                                                                                                  | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Weight   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| diagnosis          | The plan's stated diagnosis read against the observed behavior and steps in the reproduction evidence.                                                                    | The proposed diagnosis is consistent with the reproduced behavior, and the evidence does not contradict the explanation of the bug.                                                                                                                                                                                                                                                                                                                                                                                                                                                            | required |
| scope              | The plan's scope statement read against the issue description, reproduction evidence, and relevant repository facts.                                                      | The proposed change is bounded to addressing the identified issue, and its intended effects and exclusions do not introduce unrelated changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                 | required |
| cause              | The plan's explanation of the underlying cause and proposed approach read against the reproduction evidence and relevant code behavior described in the repository facts. | The proposed change addresses a cause supported by the evidence rather than merely masking the observed symptom.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | required |
| executability      | The plan's proposed approach and identified files read against the repository facts and the implementation requirements implied by the diagnosis.                         | Another developer could begin implementing the change using the plan without having to independently determine the central fix or resolve a missing implementation decision.                                                                                                                                                                                                                                                                                                                                                                                                                   | required |
| test-plan          | The plan's test plan read against the reproduction evidence's steps, inputs, and observed behavior.                                                                       | The proposed tests exercise the relevant behavior and specify observable expected results that distinguish the original bug from the intended fixed behavior.                                                                                                                                                                                                                                                                                                                                                                                                                                  | required |
| uncertainty        | The plan's stated claims, risks, and unknowns read against the reproduction evidence, the issue and thread, and the repository facts.                                     | Nothing the plan states as fact contradicts the reproduction evidence, issue, thread, or repository facts, and the plan does not report work or test results as done that have not happened. Code-level claims the package cannot verify (file names, how a function behaves) are acceptable when they are consistent with the reproduction and the proposed approach. Fail only when a stated fact conflicts with the package, an unperformed result is reported as done, or the plan treats as settled something the package shows to be open. A plan does not need a risks section to pass. | required |
| thread-conventions | The plan comment read against the issue thread's highlights and the repository-facts block describing relevant conventions.                                               | The comment addresses relevant requests or constraints raised in the thread (an empty thread adds none), does not conflict with established repository conventions, and makes no unsupported claims about work already completed. Where the repository facts state a disclosure requirement, such as an AI-use disclosure rule, the comment must satisfy it. Plans and comments in this course are drafted with AI assistance, so a stated disclosure rule applies, and a comment with no disclosure fails. A policy that only welcomes AI or asks for human review adds no requirement.       | required |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. An unclear result on a required check counts as a failure and therefore results in reject. Preferred checks, if added later, never change the verdict.
